# Канал автообновления (GRND_UPDATE)

Скрипт `grnd_adm_tools.lua` умеет обновлять себя сам: при заходе в игру он
скачивает крошечный `update.txt` с номером последней версии и, если версия
новее установленной, качает сам скрипт **рядом** (`grnd_adm_tools.lua.new`),
проверяет его, подменяет рабочий файл (старый уходит в `.bak`) и открывает
окно «АВТООБНОВЛЕНИЕ» со списком изменений и кнопкой «Перезагрузить скрипт».

## Что лежит в канале

Канал — **этот же репозиторий**, корень:

| Файл | Что внутри |
|------|------------|
| `update.txt` | только номер версии, например `1.19.224` |
| `grnd_adm_tools.lua` | сам скрипт (та версия, что названа в `update.txt`) |

Адрес канала — **метка (тег) `grnd-latest`**, а не ветка: метка не меняется
от версии к версии, поэтому у уже установленных скриптов адрес остаётся
рабочим навсегда.

Каналов в скрипте пять (порядок проб; ответивший запоминается в
`grnd_update.cfg` строкой `channel=<id>` и дальше пробуется первым):

| id | адрес | кэш |
|----|-------|-----|
| `api` | `https://api.github.com/repos/<акк>/Grnd-Tools/` (`contents/<файл>?ref=grnd-latest`) | нет |
| `statically` | `https://cdn.statically.io/gh/<акк>/Grnd-Tools/grnd-latest/` | часы |
| `githack` | `https://raw.githack.com/<акк>/Grnd-Tools/grnd-latest/` | часы |
| `raw` | `https://raw.githubusercontent.com/<акк>/Grnd-Tools/grnd-latest/` | ~5 мин |
| `jsdelivr` | `https://cdn.jsdelivr.net/gh/<акк>/Grnd-Tools@grnd-latest/` | до 12 ч |

Первым идёт **`api.github.com`**: это сам GitHub, а не CDN, поэтому сразу
после выпуска он отдаёт уже новый номер версии (зеркала в это время ещё
держат прошлый файл). Зеркала остались запасными дорогами: у них к адресу
добавляется метка времени (`?v=<минуты>`), но часть CDN строку запроса
игнорирует, поэтому «свежесть» обеспечивает именно api-канал.

Если канал отдал версию **старее** установленной (старый файл из кэша), скрипт
идёт к следующему каналу; если старым ответили все — сообщает «версия — самая
свежая», а не «нет связи с сервером».

Ответ `api.github.com` скрипт умеет читать в трёх видах: как сам файл (WinINet
ставит заголовок `Accept: application/vnd.github.raw`), как JSON с base64 в
поле `content` (и с экранированными переводами строк) и как `git/blobs/<sha>`
для файла больше мегабайта (у него в Contents API содержимого нет).

Если у игрока не работает ни один канал, `/grndupdate test` покажет ответ
каждого (всё это пишется в `grnd_update.log` рядом со скриптом).

```
https://raw.githubusercontent.com/kacarovmihail4-max/Grnd-Tools/grnd-latest/update.txt
https://raw.githubusercontent.com/kacarovmihail4-max/Grnd-Tools/grnd-latest/grnd_adm_tools.lua
```

Зеркало (то же содержимое, кэш ~12 часов; используется, если первое не
ответило):

```
https://cdn.jsdelivr.net/gh/kacarovmihail4-max/Grnd-Tools@grnd-latest/update.txt
```

В самом скрипте адрес можно переопределить строками `repo=` и `mirror=` в
`grnd_update.cfg` рядом со скриптом — без правки кода.

## Как выпустить новую версию

1. Поднять `GRND_SCRIPT_VERSION` в шапке скрипта и добавить блок изменений
   (`-- vX.Y.Z — …`) — именно из этих блоков окно обновления строит список
   «что нового» для игроков.
2. Записать тот же номер в `update.txt` (только цифры, перевод строки можно).
3. Убедиться, что стенды зелёные: `luajit tests/run_all.lua`.
4. Закоммитить и запушить ветку сессии.
5. **Передвинуть метку** на новый коммит:

```
git tag -f grnd-latest
git push -f origin refs/tags/grnd-latest
```

Порядок важен: сначала ветка (в ней уже лежат файлы), потом метка — чтобы она
никогда не указывала на версию, которой нет в репозитории.

## Проверки на стороне игры

Скрипт не ставит то, что скачал, не убедившись, что:

* файл не меньше 100 КБ (страница ошибки вместо файла — отбрасывается);
* внутри скачанного файла стоит ровно та версия, что была в `update.txt`
  (защита от «метка от старой версии» и от подмены содержимого);
* иначе — рабочий файл не трогается, в тост уходит причина, `.new` удаляется.

## Что помнить

* `update.txt` и `grnd_adm_tools.lua` в канале должны совпадать по версии —
  иначе клиенты обновление отклонит (и это правильное поведение).
* Если метка не двигалась, скрипты у игроков останутся на прежней версии:
  канал читается только на чтение, сами они ничего не публикуют.
* Токен среды (GitHub App) умеет пушить в этот репозиторий и двигать теги,
  но **не** умеет создавать gist'ы и репозитории — канал поэтому живёт
  здесь, в самом репозитории.
* Загрузка у игрока идёт двумя дорогами: штатный `downloadUrlToFile` (если
  есть) и запасной WinINet через FFI. Вторая дорога спасает, когда штатный
  загрузчик молчит или его нет в сборке MoonLoader.
